# 루나 논문 리뷰 블로그 — 운영 프롬프트 (2026-10-13 정리)

실제 초안 프롬프트는 `src/main/paperBlog.ts`의 `SYSTEM`이고, 이 문서는 그 요약과 운영 규칙이다. 규칙을 바꾸면 코드와 이 문서를 함께 고친다.

## 1. 역할
- 루나(마케팅 AI)가 논문 후보 찾기 → (대표가 고름) → 본문 검증 → 초안 작성 → 네이버 에디터 입력까지 한다.
- 발행·예약·저장은 하지 않는다. 최종 확인과 발행은 대표가 한다.
- 글쓰기는 Claude Code 구독(Pro)으로 한다. API 크레딧을 쓰지 않는다 (`npm run blog-paper`).

## 2. 글쓰기 규칙
1. 논문 본문에서 직접 확인한 사실·숫자만 쓴다. 모순되거나 불확실한 숫자는 본문에 쓰지 않고 검증 메모에 적는다.
2. 한계(이질성, 추적 기간, 표본, 출판 편향 등)를 반드시 본문에 쓴다.
3. 이 논문이 센터의 진행 순서를 증명했다고 쓰지 않는다. "논문은 방향성의 근거, 설계는 검사 결과에 맞춘다"로 구분한다.
4. 치료·완치·효과 단정, 의료행위로 읽히는 표현, 회원 후기·전후 사진 언급 금지. "~로 보고했습니다" 형태.
5. 대표 1인칭. 첫 줄 "안녕하세요, 자이언트짐 대표 이준산입니다!".
6. 제목: `정왕동헬스장) 핵심 문장`. 키워드(정왕동피티·정왕동헬스장·정왕동자세교정피티)는 자연스럽게만.
7. 본문 1,500~2,000자. 마크다운 기호 금지. 목록은 `• `, `1. `, 체크는 `✔ `.
8. 어려운 용어는 처음 나올 때 한 문장으로 풀어쓴다. 존댓말, 과장·광고 문구 금지.

9. **굵은 글씨**: 중요한 부분만 `**…**`로 표시한다 — 핵심 결론 문장, 핵심 수치, "근거가 있는 것 / 아직 확실하지 않은 것" 요약, "이 논문이 센터 순서를 증명한 것은 아님" 문장, 상담 유도 한 줄. 문단당 1~2곳, 한 곳 40자 이내, 글 전체 6~9곳. 소제목·✔ 줄·출처·※ 문구에는 쓰지 않는다.
10. **글자 크기**: 에디터 입력 후 본문 전체를 16으로 키운다(네이버 기본 15). 제목·이미지는 그대로. 끄려면 `.env`에 `BLOG_BODY_FONT_SIZE=0`.

## 3. 글 구조 (센터 최신 게시글 기준, 주제만 바꾼다)
| 순서 | 내용 |
|---|---|
| 도입 | 인사 → 독자 상황 공감 2~3문장 → "오늘은 ○○을 다룬 논문을 읽고 정리해 알아보겠습니다!" |
| 소제목 1 (느낌표) | 논문 배경·무엇인지(학술지·연도·방법·대상·규모) + 센터가 중요하게 보는 점 한 줄 |
| 소제목 2 (느낌표) | 결과 "~로 보고했습니다". 유의하지 않은 차이는 우열을 쓰지 않는다 |
| 소제목 3 (느낌표) | 한계 + "근거가 있는 것 / 아직 확실하지 않은 것" 한 줄 요약 |
| 소제목 4 (질문) | "나에게 맞는 ○○이 궁금하다면?" → ✔ 5줄 → 한 줄 결론 → 센터 5단계(1.~5.) → "이 논문이 증명한 것은 아님" |
| 소제목 5 (느낌표) | 마무리: 꾸준함, 앞으로도 한계까지 정리하겠다는 약속, 상담 유도, 💪 한 번 |
| 끝 | 출처 → 면책 문구 → AI 활용 문구 |
| 고정 블록 (프로그램이 자동 추가) | 홈페이지 → 📌센터 소개 5줄 → 💚네이버 예약 → 🏠오시는 길 → 네이버톡톡 → 📞0507-1482-3349 |

- 소제목은 정확히 5개, 각 30자 이내 한 줄, 앞뒤 빈 줄. 소제목마다 앞에 이미지가 들어간다.
- 출력 파일: 검증 메모(게시 금지) + 게시용 초안(제목·본문·카드 데이터 JSON·태그 10개 안팎).

## 4. 이미지 규칙
- 카드 3장(논문 한눈에 보기 / 근거 있는 것·약한 것 / 센터 5단계)과 배너는 "AI 제작 이미지"로 표시한다.
- **센터 사진은 `바탕화면/블로그 초안/사진` 폴더의, 모자이크가 끝나 `library.json`에 등록된 사진만** 쓴다. 한 글에 3장.
- **직전 글과 겹치지 않게** 가장 오래전에 쓴(안 쓴) 사진부터 순환한다. 사용 기록(`used.json`)은 에디터 입력이 끝까지 성공한 뒤에만 남긴다.
- 사진이 6장이면 2글마다 같은 조합이 돌아오므로, 새 사진을 계속 추가한다.

### 직접 촬영한 이미지 저장 규칙
바탕화면에만 있는 파일은 다른 곳에 같은 것이 없을 수 있으니, 촬영한 사진은 아래 규칙대로 **바로 두 곳에 나눠 저장**한다.

| 구분 | 위치 | 용도 |
|---|---|---|
| 원본 보관 | `바탕화면/블로그 초안/사진_원본/` | 모자이크 전 원본. 글에는 절대 쓰지 않는다 |
| 모자이크 확인 | `바탕화면/블로그 초안/사진_모자이크확인/` | 자동 모자이크 결과. 대표가 눈으로 확인하는 대기 폴더 |
| 승인 사진 | `바탕화면/블로그 초안/사진/` | 모자이크 확인이 끝난 사진. 글에는 여기 것만 쓴다 |

- 파일명: `원본_YYYYMMDD_번호.jpg` (원본), `photo_번호.jpg` (승인, 번호는 이어서 7, 8, …). 에디터가 파일명으로 이미지를 찾기 때문에 승인 사진은 영문·숫자 이름만 쓴다.
- 승인 사진을 넣으면 `사진/library.json`에 `"파일명": { "scene": "자세를 직접 교정하는 모습" }` 형태로 장면 설명을 반드시 추가한다. 등록되지 않은 사진은 글에 쓰이지 않는다.
- **자동 저장 도구**: `npm run blog-photo -- --file "경로"`(원본만) / `--approved --scene "장면 설명"`(모자이크 끝난 사진 등록, 폴더째도 가능). 루나 채팅에서는 `blog_photo_save`. 모자이크 여부를 모르면 승인하지 않고 원본만 저장한다. 같은 사진은 중복 저장하지 않는다.
- **얼굴 자동 모자이크**: `npm run blog-photo -- --file "원본경로" --mosaic` (루나 채팅 `blog_photo_mosaic`). 원본을 `사진_원본`에 보관하고, 얼굴을 찾아 6x6 블록으로 가린 결과를 `사진_모자이크확인/`에 둔다(글에 쓰이는 폴더 아님). 탐지기는 YuNet + Haar 합집합이라 놓치는 것보다 과하게 가리는 쪽이다. EXIF(위치·기기 정보)는 저장하지 않는다.
- **자동 탐지는 놓칠 수 있다**: 결과 파일을 대표가 직접 열어 작은 얼굴·옆모습·거울 속 얼굴까지 가려졌는지 확인한 뒤에만 `--approved --scene "…"`로 등록한다. 얼굴 0개로 나오면 놓친 것일 수 있으니 등록하지 않는다.
- 처음 한 번 `npm run setup-face-mosaic`(파이썬 환경, `tools/.venv`)이 필요하다. 이 PC에는 설치돼 있다.
- 두 폴더는 OneDrive 바탕화면 아래에 있어 자동 동기화되지만, 월 1회 외장/다른 위치에 복사 백업한다.

## 5. 대표 확인 사항 (발행 전)
1. 검증 메모의 "불확실해서 쓰지 않은 숫자"와 본문 숫자를 논문 원문과 대조.
2. 마지막 AI 문구 "논문 내용은 대표가 확인했습니다" — 확인한 뒤에만 발행.
3. 배너 링크(`ziant.com`)와 장소 2곳(1호점·2호점)이 맞는지 미리보기로 확인.
4. 로그인된 블로그 계정(`koreafitnessdata`)이 올릴 블로그가 맞는지.

## 6. 실행 명령
- 후보 찾기: `npm run blog-paper -- --topic "주제"`
- 초안 작성: `npm run blog-paper -- --pmcid PMC…` (또는 `--pmid`, `--doi`, `--pdf`)
- 에디터 입력: `npm run blog-paper -- --fill` (전용 크롬 `chrome-ai-profile`에 네이버 로그인 필요, 에디터가 비어 있어야 함)
