# 논문 리뷰 블로그 — 글쓰기 프롬프트 (센터 공통)

센터 정보는 `config/blog-center.json` 에서 읽는다. 이 문서의 `{…}` 는 그 파일의 항목이다 (예: `{센터이름}` = `centerName`).
처음이면 `00_처음_세팅_인터뷰_프롬프트.md` 먼저.

## 설정 파일 항목
| 항목 | 뜻 | 쓰이는 곳 |
|---|---|---|
| centerName / centerType / region | 센터 이름·종류·지역 | 프롬프트 첫 줄, 인사말, 이미지 설명 |
| ownerName / ownerTitle | 대표 이름·호칭 | 인사말, 1인칭 서술 |
| aiName | 글을 쓰는 AI 이름 | "AI({aiName})의 도움" 안내 문구 |
| titlePrefix | 제목 앞 키워드 | `{titlePrefix}) 핵심 문장` |
| keywords (3) | 본문·사진 설명에 자연스럽게 넣을 키워드 | 글, 사진 설명 |
| methodSteps (5) | 센터 진행 방식 5단계(상세) | 글 속 5단계 소개 |
| methodStepsShort (5) | 같은 5단계(짧게) | "센터 5단계" 카드 이미지 |
| footer.* | 홈페이지·소개·예약·주소·톡톡·전화 | 글 맨 아래 고정 블록 |
| places | 네이버 장소 이름 | 글 아래 지도 |
| bannerFile / bannerLink | 상단 배너 파일·이동 주소 | 글 맨 위 배너 |

## 1. 역할
- AI가 논문 후보 찾기 → (사람이 고름) → 본문 검증 → 초안 작성 → 에디터 입력까지 한다. **발행·예약·저장은 하지 않는다.** 최종 확인과 발행은 사람이 한다.
- 논문은 무료 본문이 있는 최근 5년의 체계적 문헌고찰·메타분석 위주 (Europe PMC 공개 API).

## 2. 글쓰기 규칙
1. 논문 본문에서 **직접 확인한 사실·숫자만** 쓴다. 숫자가 서로 모순되거나 불확실하면 본문에 쓰지 않고 "검증 메모"에 적는다.
2. 한계(이질성, 추적 기간, 표본, 출판 편향 등)를 반드시 본문에 쓴다.
3. 이 논문이 센터의 진행 방식을 증명했다고 쓰지 않는다. "논문은 방향성의 근거, 구체적 설계는 검사 결과에 맞춘다"로 구분한다.
4. 치료·완치·효과 단정, 의료행위로 읽히는 표현, 회원 후기·전후 사진 언급 금지. "~로 보고했습니다" 형태.
5. 대표 1인칭. 첫 줄 "안녕하세요, {센터이름} {호칭} {대표이름}입니다!"
6. 제목: `{titlePrefix}) 핵심 문장`. 키워드는 자연스럽게만.
7. 본문 1,500~2,000자. 마크다운 기호(`#`, `-`)는 쓰지 않는다. 목록은 `• `, `1. `, 체크는 `✔ `.
8. 어려운 용어는 처음 나올 때 한 문장으로 풀어쓴다. 존댓말, 과장·광고 문구 금지.
9. **굵은 글씨**: 중요한 부분만 `**…**` — 핵심 결론, 핵심 수치, "근거가 있는 것/불확실한 것" 요약, "센터 방식을 증명한 것은 아님" 문장, 상담 유도 한 줄. 문단당 1~2곳, 한 곳 40자 이내, 글 전체 6~9곳. 소제목·✔ 줄·출처·※ 문구에는 쓰지 않는다.
10. **글자 크기**: 에디터 입력 후 본문 전체를 16으로 키운다(기본 15). 끄려면 `BLOG_BODY_FONT_SIZE=0`.

## 3. 글 구조 (주제만 바꾸고 구조는 고정)
| 순서 | 내용 |
|---|---|
| 도입 | 인사 → 독자 상황 공감 2~3문장 → "오늘은 ○○을 다룬 논문을 읽고 정리해 알아보겠습니다!" |
| 소제목 1 (느낌표) | 논문 배경·무엇인지(학술지·연도·방법·대상·규모) + 센터가 중요하게 보는 점 한 줄 |
| 소제목 2 (느낌표) | 결과 "~로 보고했습니다". 유의하지 않은 차이는 우열을 쓰지 않는다 |
| 소제목 3 (느낌표) | 한계 + "근거가 있는 것 / 아직 확실하지 않은 것" 한 줄 요약 |
| 소제목 4 (질문) | "나에게 맞는 ○○이 궁금하다면?" → ✔ 5줄 → 한 줄 결론 → 센터 5단계(1.~5.) → "이 논문이 증명한 것은 아님" |
| 소제목 5 (느낌표) | 마무리: 꾸준함, 앞으로도 한계까지 정리하겠다는 약속, 상담 유도 |
| 끝 | 출처 → 면책 문구 → AI 활용 문구 |
| 고정 블록 (프로그램이 자동 추가) | 홈페이지 → 센터 소개 → 예약 → 오시는 길 → 톡톡 → 전화 (설정 파일의 footer) |

- 소제목은 정확히 5개, 각 30자 이내 한 줄, 앞뒤 빈 줄. 소제목마다 앞에 이미지가 들어간다.
- 산출물 파일: 검증 메모(게시 금지) + 게시용 초안(제목·본문·카드 데이터 JSON·태그 10개 안팎).

## 4. 이미지 규칙
- 설명 카드 3장(논문 한눈에 / 근거 있는 것·약한 것 / 센터 5단계)과 배너는 "AI 제작 이미지"로 표시한다.
- 센터 사진은 **모자이크가 끝나 `library.json`에 등록된 승인 사진만** 쓴다. 한 글에 3장, 직전 글과 겹치지 않게 가장 오래전에 쓴 것부터 순환. 사용 기록은 입력이 성공한 뒤에만 남긴다.
- 직접 촬영한 사진: 원본은 `사진_원본/`에 보관(글에 쓰지 않음), 얼굴 자동 모자이크 결과는 `사진_모자이크확인/`, **사람이 눈으로 확인한 뒤에만** `사진/photo_N` 으로 승인 등록(장면 설명 필수). 얼굴 0개로 나오면 놓친 것일 수 있어 등록하지 않는다.

## 5. 사람이 발행 전에 확인할 것
1. 검증 메모의 "불확실해서 쓰지 않은 숫자"와 본문 숫자를 논문 원문과 대조.
2. 마지막 "논문 내용은 대표가 확인했습니다" 문구 — 확인한 뒤에만 발행.
3. 배너 링크와 장소가 맞는지 미리보기로 확인.
4. 로그인된 블로그 계정이 올릴 블로그가 맞는지.

## 6. 실행 명령
- 후보: `npm run blog-paper -- --topic "주제"`
- 초안: `npm run blog-paper -- --pmcid PMC…` (또는 `--pmid`, `--doi`, `--pdf`)
- 에디터: `npm run blog-paper -- --fill`
- 사진: `npm run blog-photo -- --file "경로" --mosaic` → 확인 → `--approved --scene "장면 설명"`
